# سامانه پیش‌فاکتور من

سامانه مستقل PHP برای صدور پیش‌فاکتور چندشرکتی روی cPanel، با ورود OTP یا رمز عبور، داشبورد کاربری، پنل مدیریت، IPPanel، مشتریان و کالا/خدمات هوشمند، ذخیره آخرین قیمت، لوگو/مهر/امضا و خروجی PDF، PNG، JPG و چاپ.

## نیازمندی‌ها

- PHP 8.1 یا بالاتر
- MySQL 8 یا MariaDB 10.5+
- افزونه‌های PHP: pdo_mysql، curl، mbstring، fileinfo و json
- گواهی SSL فعال و Apache mod_rewrite

پروژه به Composer، Node.js، SSH یا CDN نیاز ندارد و کتابخانه‌های خروجی داخل بسته قرار گرفته‌اند.

تمام فایل‌های JavaScript و CSS موردنیاز شامل PDF، خروجی تصویر و تقویم جلالی داخل پوشه public/assets/vendor قرار دارند. رابط سامانه برای اجرا به CDN یا اینترنت بین‌الملل وابسته نیست؛ فقط ارسال واقعی OTP نیازمند دسترسی سرور به API سامانه IPPanel است.

## نصب خودکار روی cPanel

1. فایل ZIP را در مسیری مانند public_html/pishfactor استخراج کنید.
2. در cPanel یک دیتابیس MySQL و کاربر دیتابیس ایجاد و ALL PRIVILEGES را فعال کنید.
3. آدرس example.com/pishfactor/install/install.php را باز کنید.
4. وضعیت پیش‌نیازها را مشاهده و مشخصات دیتابیس و IPPanel را وارد کنید.
5. تهیه Backup را تأیید و نصب را اجرا کنید.
6. اینستالر تمام فایل‌های نسخه‌دار را به‌ترتیب اجرا و فایل .env را ایجاد می‌کند.

در همین مرحله نام، موبایل و رمز اولین مدیر سامانه نیز دریافت می‌شود. مدیر می‌تواند پس از ورود، کاربران، کالاها و خدمات و تنظیمات IPPanel را مدیریت کند.

پس از نصب نیز همین مسیر، صفحه بررسی و بروزرسانی را نمایش می‌دهد و نصب اولیه را تکرار یا اطلاعات اتصال را بازنویسی نمی‌کند.

## سیستم بروزرسانی خودکار

تغییرات دیتابیس در پوشه install/updates قرار می‌گیرند. نام هر فایل دقیقاً شماره نسخه Semantic Version است:

~~~text
install/updates/
  1.0.0.php
  1.0.0.sql
  1.1.0.php
  1.2.0.php
  1.2.1.php
  1.2.2.php
  1.2.3.php
  1.2.4.php
  1.3.0.php
  1.3.1.php
  1.4.0.php
  1.4.1.php
  1.4.2.php
  1.4.3.php
~~~

جدول schema_migrations نسخه، توضیح، SHA-256 فایل و زمان اجرا را ثبت می‌کند. با مراجعه مجدد به install/install.php:

1. نسخه‌های موجود و اجراشده مقایسه می‌شوند.
2. تمام نسخه‌های اجرا‌نشده با version_compare مرتب می‌شوند.
3. بروزرسانی‌ها یک‌به‌یک از قدیمی‌ترین تا جدیدترین اجرا می‌شوند.
4. هر نسخه فقط بعد از اجرای موفق در دیتابیس ثبت می‌شود.
5. نسخه اجراشده دوباره اجرا نمی‌شود.
6. اگر فایل یک نسخه قدیمی پس از اجرا تغییر کرده باشد، بروزرسانی متوقف می‌شود.
7. قفل MySQL از اجرای هم‌زمان دو بروزرسانی جلوگیری می‌کند.

برای مثال اگر نسخه 1.0.1 نصب باشد و فایل‌های 1.0.2 تا 1.0.8 در بسته موجود باشند، همه آن‌ها دقیقاً به همین ترتیب اجرا خواهند شد.

نمونه تنظیم:

~~~dotenv
APP_URL=https://example.com/pishfactor
APP_ENV=production
APP_DEBUG=false
APP_KEY=یک-رشته-تصادفی-طولانی
SESSION_SECURE=true
DB_HOST=localhost
DB_PORT=3306
DB_NAME=cpuser_pishfactor
DB_USER=cpuser_pfuser
DB_PASS=رمز-قوی
~~~

## تنظیم IPPanel

در پنل IPPanel یک Access Key و Pattern برای OTP بسازید. نام متغیر الگو مثلاً code باشد:

~~~dotenv
IPPANEL_API_KEY=کلید-دسترسی
IPPANEL_AUTH_PREFIX=
IPPANEL_FROM_NUMBER=+983000505
IPPANEL_PATTERN_CODE=کد-پترن
IPPANEL_OTP_PARAM=code
OTP_TTL_SECONDS=120
OTP_RESEND_SECONDS=60
~~~

سامانه از API جدید IPPanel Edge و مسیر POST https://edge.ippanel.com/v1/api/send استفاده می‌کند. در بیشتر حساب‌ها IPPANEL_AUTH_PREFIX خالی است؛ اگر حساب شما نیاز داشت مقدار آن را Bearer همراه یک فاصله قرار دهید.

برای آزمایش بدون پیامک، موقتاً APP_ENV=local و IPPANEL_API_KEY را خالی بگذارید؛ کد آزمایشی در صفحه ورود نشان داده می‌شود. این حالت در سایت اصلی فعال نماند.

## گردش کار

1. ورود با شماره موبایل و OTP
2. ثبت شرکت و بارگذاری لوگو، مهر و امضا
3. انتخاب یا ایجاد مشتری در صفحه سند
4. جست‌وجوی آنی کالا/خدمت همراه واحد و آخرین قیمت
5. ذخیره پیش‌نویس و صدور نهایی
6. پیش‌نمایش و دریافت PDF، PNG، JPG یا چاپ A4

## ورود و داشبورد

- کاربران می‌توانند با OTP یا رمز عبور وارد شوند.
- کاربری که رمز ندارد، ابتدا با OTP وارد و از «پروفایل و رمز عبور» برای خود رمز تعریف می‌کند.
- پس از ورود، کاربر به داشبورد شخصی شامل آمار شرکت‌ها، مشتریان، اقلام و پیش‌فاکتورها هدایت می‌شود.
- نقش مدیر علاوه بر داشبورد شخصی به بخش مدیریت سامانه دسترسی دارد.
- تاریخ صدور و اعتبار با تقویم جلالی انتخاب و در پیش‌نمایش و خروجی نیز جلالی نمایش داده می‌شود.
- پیش از خروجی می‌توان قالب رسمی، مدرن یا کم‌جوهر و اندازه A4، A5 یا Letter را انتخاب کرد.
- لینک مشاهده مشتری با رمز مستقل، تاریخ انقضا و قابلیت لغو ساخته می‌شود و از طریق ایمیل، IPPanel یا پیام‌رسان‌ها قابل ارسال است.
- مقدار استاندارد میلادی فقط در لایه دیتابیس نگهداری می‌شود تا مرتب‌سازی و محاسبات تاریخ مطمئن باقی بماند.

## پنل مدیریت

- مشاهده و فعال/مسدودکردن کاربران
- تعیین نقش کاربر یا مدیر با جلوگیری از حذف آخرین مدیر
- مشاهده و ویرایش کالا و خدمات تمام کاربران و شرکت‌ها
- مشاهده آمار کلی سامانه
- تنظیم نام سامانه، IPPanel، Pattern و سیاست زمانی OTP
- رمزگذاری Access Key پیامک در دیتابیس با APP_KEY
- ثبت تغییرات مدیریتی در Audit Log
- طراح فرم‌های خروجی با امکان ساخت چند فرم، تعیین فرم پیش‌فرض و انتخاب کاغذ A3، A4، A5، A6، Letter یا Legal
- فعال یا غیرفعال‌کردن ستون‌های کد، واحد، تعداد، قیمت، تخفیف، مالیات و جمع
- کنترل نمایش مشخصات فروشنده و خریدار، توضیحات، شرایط پرداخت، امضا و پاورقی
- تغییر ترتیب بخش‌های خروجی و تعیین اندازه، جهت و سبک هر فرم

## ارتقا از نسخه‌های قبلی

1. ابتدا از دیتابیس Backup کامل بگیرید.
2. فایل‌های نسخه جدید را روی هاست جایگزین کنید؛ فایل .env و پوشه storage/uploads را حذف نکنید.
3. آدرس install/install.php را باز کنید.
4. اگر نسخه قبلی مدیر و رمز دارد، مدیر را از فهرست انتخاب و فقط رمز او را وارد کنید.
5. برای نسخه‌های بسیار قدیمی بدون نقش مدیر، مقدار APP_KEY فایل .env و مشخصات مدیر جدید را وارد کنید.
6. فهرست بروزرسانی‌های در انتظار نمایش داده و به‌ترتیب اجرا می‌شود.

پیش از اجرای Migrationها، اینستالر به‌صورت خودکار Backup کامل و قابل بازیابی دیتابیس را در storage/backups ایجاد می‌کند و لینک امن دانلود آن را در همان صفحه نمایش می‌دهد. پوشه Backup مستقیماً از وب قابل مشاهده نیست.

اطلاعات شرکت و مشتری داخل سند به‌صورت snapshot ذخیره می‌شود. پس از صدور نهایی، قیمت اقلام در تاریخچه ثبت و آخرین قیمت کاتالوگ به‌روزرسانی می‌شود.

## امنیت و نگهداری

- کلید IPPanel و رمز دیتابیس فقط در .env نگهداری می‌شوند.
- OTP به‌صورت Hash ذخیره و پس از مصرف باطل می‌شود.
- ارسال OTP بر اساس موبایل و IP محدود شده است.
- تمام عملیات تغییردهنده با CSRF محافظت می‌شوند.
- Queryها پارامتری و مالکیت داده‌ها بر اساس کاربر و شرکت کنترل می‌شود.
- فایل‌ها از نظر MIME و حجم بررسی و اجرای اسکریپت در Storage مسدود شده است.
- در محیط اصلی APP_DEBUG=false باشد.
- از دیتابیس و پوشه storage/uploads روزانه Backup بگیرید.

## محدودیت‌های نسخه 1.0

- PDF/PNG/JPG در مرورگر ساخته می‌شوند؛ برای اسناد بسیار طولانی، چاپ و Save as PDF مرورگر مطمئن‌تر است.
- تاریخ دیتابیس میلادی است؛ نمایشگر شمسی پیشرفته در نسخه بعد قابل افزودن است.
- نقش‌های چندکاربره، لینک عمومی تأیید و اتصال سامانه مؤدیان در مدل توسعه پیش‌بینی شده‌اند اما در رابط نسخه 1.0 فعال نیستند.

## ساختار

install/updates/      فایل‌های شماره‌دار تغییرات دیتابیس
config/version.php    نسخه فعلی برنامه
public/assets/       CSS، JavaScript و کتابخانه‌های محلی خروجی
resources/lang/      فایل‌های زبان فارسی و انگلیسی
resources/views/     رابط و قالب‌ها
storage/             لاگ‌ها و فایل‌های شرکت‌ها
tests/               آزمون‌ها
~~~
